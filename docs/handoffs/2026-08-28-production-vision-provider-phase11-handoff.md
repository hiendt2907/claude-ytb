## 7. Adapter architecture

```text
VisualRequest
    -> technically-valid JudgeCandidate[]
    -> VisualJudge port (unchanged Phase 10)
    -> providers/vision registry
    -> XkiroVisualJudge
    -> XkiroVisionTransport
    -> xKiro Chat Completions (real image input)
    -> strict CandidateEvaluation[]
    -> Phase-10 ranked selector
    -> VisualManifest
```

`src/ytb_pipeline/providers/vision/__init__.py` is a capability-specific registry, deliberately separate from image generation. It registers only `xkiro`. `render/visual_assets.py` resolves the adapter lazily only when an opted-in `vlm_ranked` selection needs a fresh evaluation. Tests may still inject a fake Judge.

## 8. Image transport format

For one Shot, all technically-valid candidates are sent in one comparative request. For each candidate the adapter appends:

1. a text label containing exact `candidate_index` and `asset_id`;
2. an `image_url` content part containing a base64 data URI.

Candidate order is preserved. Local file paths are not sent in prompt text. The adapter uses the existing xKiro `/v1/chat/completions` endpoint and OpenAI-compatible mixed-content request shape.

## 9. MIME and size handling

Phase 11 supports the formats generated by the current visual path: PNG and JPEG. MIME is detected from file signatures, not trusted extensions. Unsupported bytes fail explicitly.

Before encoding, the adapter rereads each original file, recomputes SHA-256, and requires it to match the `JudgeCandidate.content_sha256`. Pillow must then decode and verify the image successfully, the decoded format must agree with the PNG/JPEG magic bytes, and decoded size is capped at 16,000,000 pixels. The default encoded-file limit is 8 MiB. The current generated dimensions (1344×768 landscape or 832×1216 portrait) do not require preview conversion, so no temporary derivative is created. Original assets are never modified.

The smoke-only geometric PNG is created under `TemporaryDirectory` and removed reliably. It never enters `AssetRegistry`, candidate cache, or repository `assets/`.

## 10. Judge prompt

The provider receives only bounded request context: visual intent, named characters, semantic constraints, target dimensions, scene/shot IDs, candidate labels, and candidate image bytes.

It is instructed to evaluate request fidelity, required character/object/action/environment, grounded continuity, composition, contradictions, and required readable text. It explicitly forbids beauty, attractiveness, body, age, gender, and racial desirability scoring. No `.env`, API key, source tree, global registry history, full script, ComfyUI workflow, or unrelated project data is sent.

## 11. Strict response path

The transport returns assistant text only. `XkiroVisualJudge` JSON-decodes it and passes it to the unchanged Phase-10 `parse_judge_payload()`.

Unknown/missing/duplicate asset IDs, unknown fields, incomplete candidate sets, invalid score types/ranges, and unknown hard-failure codes remain rejected. The adapter does not add a permissive production parser.

## 12. Repair

Malformed structured output gets exactly one repair request. The repair resends the same candidate images and bounded context plus the validation error. A second malformed result becomes `JudgeInfrastructureError`. Transport failures do not trigger unbounded retries.

## 13. Error mapping

The adapter maps these to infrastructure failures, never semantic rejection:

- timeout/network failure;
- HTTP 401/403 authentication;
- HTTP 413 payload too large;
- HTTP 429 rate limit;
- HTTP 5xx unavailable;
- invalid/empty provider response;
- invalid model catalog response;
- unknown or `vision=false` model;
- missing/changed candidate bytes;
- oversized, corrupt, undecodable, or unsupported media.

No error is converted into a fake passing evaluation.

## 14. Configuration

Production profiles keep the Phase-10 contract:

```json
{
  "candidate_count": 3,
  "selection_policy": "vlm_ranked",
  "visual_judge": {
    "enabled": true,
    "provider": "xkiro",
    "model": "qwen/qwen3.8-max:free",
    "policy_version": "phase11-v1",
    "minimum_score": 0.5,
    "hard_fail_on_judge_error": false
  }
}
```

No existing profile was changed or globally enabled. `candidate_count=1` and `first_valid` remain defaults.

`VISUAL_JUDGE_PROVIDER` and `VISUAL_JUDGE_MODEL` are operator-smoke defaults only; they do not opt a profile into ranked selection. Settings fail fast if only one is set. `--status` reports configured/registered/active state plus provider/model without making a billed Judge call.

## 15. Secrets handling

The adapter reuses `XKIRO_API_KEY` from Pydantic settings/`.env`. `.env.example` contains an empty placeholder only. No key is persisted in evaluation/candidate/manifest artifacts, logs, docs, prompts, or Git. Base64 payloads and raw media are not logged.

## 16. Evaluation-cache interaction

Phase-10 `visual_evaluations.json` behavior is unchanged. `render/visual_assets.py` checks the whole-set evaluation identity before resolving or instantiating the production adapter. With unchanged request, original candidate SHA values, provider, model, policy, and contract version, the persisted evaluation is reused with zero xKiro call.

## 17. Provider/model invalidation

Provider/model identity remains part of evaluation context and selector fingerprint. Changing either invalidates evaluation and selection only. Existing candidate slots, media bytes, and immutable `AssetRecord`s remain intact; no ComfyUI regeneration occurs.

## 18. Fallback

Phase-10 behavior is preserved exactly. Infrastructure failure with `hard_fail_on_judge_error=false` records `fallback_first_valid` plus the error and selects deterministic first-valid media. With the flag true, `visual_assets` fails. Fallback state is retried on resume rather than masquerading as a cached semantic success.

## 19. Semantic fail-closed

A successful Judge response in which every candidate hard-fails or remains below `minimum_score` still fails the Shot closed. It never falls back to first-valid. Phase 11 adds no generate→reject→regenerate loop.

## 20. Operator smoke command

Required environment/config:

```bash
XKIRO_API_KEY=<configured in .env; never put in shell history/docs>
VISUAL_JUDGE_PROVIDER=xkiro
VISUAL_JUDGE_MODEL=qwen/qwen3.8-max:free
```

Status only:

```bash
PYTHONPATH=src .venv/bin/python -m ytb_pipeline.tools.smoke_visual_judge --status
```

Self-proving image transport:

```bash
PYTHONPATH=src .venv/bin/python -m ytb_pipeline.tools.smoke_visual_judge --generate-probe
```

Manual local image:

```bash
PYTHONPATH=src .venv/bin/python -m ytb_pipeline.tools.smoke_visual_judge \
  --image /absolute/path/candidate.png \
  --intent "Describe the exact visual requirement to evaluate"
```

The command exits `0` on a strict valid result (`--generate-probe` additionally requires the hidden blue-triangle facts), `1` on provider/schema/observation failure, and `2` on missing/invalid operator arguments/config.

Common errors: unset paired Judge settings; missing xKiro key; configured model absent from catalog or `vision=false`; corrupt/unsupported/non-PNG/JPEG bytes; file over 8 MiB or decoded image over 16,000,000 pixels; authentication/rate-limit/provider/network failure; malformed output after one repair.
